# Prototype interactive handout booklets

TD Suitcase → Documents & menus → Handouts → Add handout / booklet. Upload a PDF (up to 5 MB). PDF.js checks it locally before upload; unlocked PDFs up to 500 PDF sheets are accepted. PDF handouts automatically become booklets and stay hidden. Preview / edit opens the reader; Show booklet to travelers releases it into Essentials → Handouts. Hide booklet removes the listing and blocks direct metadata and PDF URLs for guests. Existing PDF handouts have Make interactive booklet, which validates the PDF and returns it to hidden for review. Replacements also return to hidden. Images and other document collections keep their existing behavior. A new upload uses the filename as a suggested title; Update title remains available.

The booklet wraps the original PDF; it does not rewrite the content or generate text. Guests can swipe in both directions, use previous/next buttons, jump to a page, use keyboard arrows, zoom up to 400%, pinch and drag the zoomed page. Fit page resets zoom. The reader includes accessible page text and safe external/internal PDF navigation links. Scanned pages remain images; no OCR runs automatically. Original PDF download is retained for accessible reader apps. Reduced-motion preferences disable page transition animation.

PDF.js worker, fonts, CMaps and image decoding assets are served from the same site, with no third-party conversion service. The worker is the existing guest-scan worker matching the installed PDF.js version. Run scripts/prepare-booklet-assets.mjs after a PDF.js update and keep the scanner worker in sync. PDF JavaScript evaluation is disabled and only http/https/mailto/tel annotation links are offered. Only the current printed page is rendered, with a pixel cap and task cancellation to limit memory. Automatic layout splits landscape/wide sheets (width/height ≥ 1.2) into left then right pages while keeping portrait sheets whole. TD page-layout controls can keep complete PDF sheets or force left/right or right/left splitting; changing layout hides the booklet for preview. Text, links, navigation, page numbers and zoom use the selected half-page. The original PDF file is preserved.

Storage uses existing private tour-resources entries and file blobs. booklet:true marks PDF handouts; type and booklet metadata are returned by listing. Hidden/deleted booklets are omitted from anonymous lists. GET ?booklet=id and ?file=id both apply the existing visibility/TD checks with no-store responses. Upload/conversion/reveal/hide keep TD authentication, same-origin protection and conditional writes. Reader availability is checked on focus and every 30 seconds; hiding clears the active canvas/text/links on the next check. Previously downloaded copies cannot be recalled.

The linked external layout example could not be inspected under this workspace's domain policy. The reader follows the requested swipe/zoom behavior and existing Soft Forest styling.

Validation: tests/resource-auth.mjs covers upload defaults, conversion, replacement, CSRF, stale revisions, guest metadata/file blocking, hidden listing privacy, TD preview and deletion. Local browser tests use a real three-page PDF and real same-site PDF.js worker/assets with API fixtures; they cover upload validation, malformed replacements, forward/back touch swipes, pinch/button zoom, page text/links, phone/tablet widths and hide-while-open behavior. Live is not changed.

## Five-megabyte transport

PDF handouts use staged uploads with 2 MB binary-equivalent pieces, keeping base64 JSON requests below hosted-function payload limits. TD authentication and same-origin checks precede every upload operation. A private 30-minute upload record pins the target resource revision and expected byte count. Parts have exact lengths, bounded indices and idempotent writes. Finish checks all parts, the 5 MB ceiling and PDF signature, then conditionally replaces the resource and leaves it hidden. Missing parts, conflicts or expired uploads do not replace the existing document. Cancellation removes temporary pieces; later upload starts sweep expired records.

New resource metadata records original byte size. PDFs over 3 MB are also fetched in 2 MB response pieces for reader loading and original-file downloads, avoiding binary-response transport limits. Every part checks the normal visibility/TD permission and source version; hiding blocks subsequent parts. Reassembled bytes are verified against expected lengths.

Validation: tests/booklet-upload.mjs covers exact 5 MB acceptance, >5 MB rejection, complete upload/download reconstruction, small request sizes, TD/CSRF, duplicate parts, incomplete uploads, stale revisions, cancellation/expiry, layout persistence and page planning. Browser checks use an actual exact-5-MB valid PDF containing two side-by-side sheets, verifying four individual pages with correct text and pixel colors, touch swipes, zoom, saved layout override and a byte-identical original PDF download.
